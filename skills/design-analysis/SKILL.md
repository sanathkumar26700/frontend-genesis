# Design Analysis


## Purpose

Extract implementation-relevant visual and interaction requirements from
design artifacts without inventing product behavior.

## Procedure

1. Identify screens and states.
2. Identify hierarchy/layout.
3. Identify spacing/typography/tokens when specified.
4. Identify responsive behavior.
5. Identify interaction states.
6. Identify assets.
7. Map to existing repository primitives.
8. Separate explicit design decisions from inference.
9. Record missing states.

## Rule

A screenshot can establish visual evidence. It cannot establish an unstated
business rule.


## Universal skill rules

- Treat repository evidence as potentially stale.
- Distinguish Observed, Inferred, and Unknown.
- Do not invent business requirements.
- Do not invent undocumented API behavior.
- Prefer existing repository patterns.
- Do not introduce dependencies or abstractions without justification.
- Report uncertainty at the decision boundary where it matters.
- Never claim verification that was not actually performed.
