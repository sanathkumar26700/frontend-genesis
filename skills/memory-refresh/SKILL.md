# Memory Refresh


## Purpose

Audit project memory and prevent stale knowledge from influencing new work.

## Procedure

1. Enumerate high-impact memory.
2. Identify entries affected by recent changes.
3. Re-check API/state/testing/UI/package architecture first.
4. Mark stale/contradicted entries.
5. Confirm current patterns from representative files.
6. Archive obsolete knowledge.
7. Record failed assumptions.
8. Produce a memory-health summary.

High-impact memory deserves more frequent verification than cosmetic conventions.


## Universal skill rules

- Treat repository evidence as potentially stale.
- Distinguish Observed, Inferred, and Unknown.
- Do not invent business requirements.
- Do not invent undocumented API behavior.
- Prefer existing repository patterns.
- Do not introduce dependencies or abstractions without justification.
- Report uncertainty at the decision boundary where it matters.
- Never claim verification that was not actually performed.
